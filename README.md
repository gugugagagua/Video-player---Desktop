# 视频集播放器（Windows 桌面版）
#该软件由AI辅助完成

**当前版本：1.7.0**

> Android 版见另一仓库 [https://github.com/gugugagagua/Video-player]

## 技术栈

- Python 3.10+ / PyQt6（Qt 6）
- **libmpv**（通过 python-mpv，视频播放后端；自带全套解码与硬件加速）
- PyAV（读关键帧索引，把缩略图锚定到关键帧上抽取）
- OpenCV-Python（首帧提取、时长探测、悬停按需抽帧、抽帧退路）
- multiprocessing（缩略图雪碧图分段并发生成）
- Pillow（封面图片格式转换）
- SQLite3（Python 内置，数据持久化）
- PyQt6.QtSvg（运行时绘制可着色的 Material 图标）
- PyInstaller + Inno Setup（打包与安装包）

## 功能对照

| Android 版功能 | 桌面版实现 |
|---------------|-----------|

| 分组管理（新建 / 重命名 / 删除 / 移动） | 分组显示为**文件夹卡片**，点击**逐层进入**，右键可重命名 / 设置封面 / 删除 |
| 分组封面 | 从组内任一视频集的封面中选择 |
| 播放列表、上一集 / 下一集 | 播放页右侧边栏 + 底部控制栏 |
| 播放进度记忆（续播） | `collections.last_video_id` + `videos.last_position`，退出 / 返回首页 / 切集时保存 |

> 桌面版不提供应用内音量调节，直接用系统音量即可。

## 构建

### 依赖准备

除 `pip install -r requirements.txt` 外，**播放功能还需要 `libmpv-2.dll`**（约 115 MB）：

1. 打开 <https://github.com/shinchiro/mpv-winbuild-cmake/releases>，下载最新的 `mpv-dev-x86_64-*.7z`（约 30 MB）
2. 用 7-Zip 或 Windows 自带的 `tar -xf` 解压，取出其中的 `libmpv-2.dll`，放到项目的 `libmpv\` 目录下

```
视频集播放器\
└── libmpv\
    └── libmpv-2.dll
```

> 该文件太大未纳入版本库（已加进 `.gitignore`）。`build.bat` 会先检查它，缺失时直接报错退出。
>
> 打包时用 `--add-binary "libmpv\libmpv-2.dll;."` 放进 `_internal\`；程序启动时会把该目录加进 `%PATH%` —— 因为 `python-mpv` 是用 `ctypes.CDLL("libmpv-2.dll")` **按 `%PATH%` 查找**的，不认 `os.add_dll_directory`。

### 源码运行

```powershell
pip install -r requirements.txt
python main.py
```

### 打包为免安装程序

```
build.bat
```

产物位于 `dist\视频集播放器\`（目录模式，非单文件）。

> **改动打包入口时注意**：缩略图生成使用了多进程，`main.py` 顶部的 `multiprocessing.freeze_support()` 必须保持在**所有其它导入之前**。否则打包后 spawn 出来的子进程会重新拉起整个应用（表现为出现多个窗口、批量任务重复执行）。
>
> PyAV 自带 FFmpeg 动态库，PyInstaller 自带的 hook 会自动收集（约 64 MB），**不需要**额外的 `--collect-all av`。

### 制作安装包

需先安装 [Inno Setup 6](https://jrsoftware.org/isdl.php)，然后：

```powershell
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer.iss
```

产物位于 `installer_output\`。修改应用名 / 版本号只需改 `installer.iss` 顶部的 `#define`。

## 使用说明

### 媒体库目录（推荐）

每个**视频集 = 一个文件夹**，把视频按以下层级放置：

```
任意位置/
├── 电视剧A/          ← 自动成为一个视频集
│   ├── cover.png     ← 可选，作为封面
│   ├── --01.mp4
│   └── --02.mp4
├── 纪录片B/          ← 另一个视频集
│   └── ...
```

- 支持的视频格式：`mp4 / avi / mkv / mov / wmv / flv / webm / m4v / mpg / mpeg / 3gp`
- 文件按**自然排序**排列：`--1` → `--2` → `--10`（而不是字典序的 `--1` → `--10` → `--2`）
- 扫描为**单层**：文件夹内的视频即该视频集的内容，不再递归更深层级

### 导入视频集

两种方式：

- 首页底部 **「+ 导入视频集」** 按钮
- 菜单栏 **文件 → 导入视频集**

选择文件夹后自动扫描入库。若该文件夹已导入，会按当前文件重新排序（可直接用来自动同步新增 / 删除的文件）。

### 分组与视频集

- 首页根层：分组显示为**文件夹卡片**，与未分组的视频集混排
- 点击文件夹**进入该分组**，顶部显示「← 返回全部 / 分组名」面包屑
- **右键分组**：重命名 / 设置分组封面 / 删除（组内视频集不会被删除）
- **右键视频集**：重命名 / 设置封面 / 提取首帧 / 新建分组（移入此集）/ 移动到分组 / 移出分组 / 删除
- **拖拽卡片**可自由排序，顺序写入数据库长期保存

### 封面

每个视频集最多只有一个 `cover.png`，保存在视频集文件夹根目录：

| 方式 | 说明 |
|---|---|
| 设置封面（从本地图片） | 选择 png / jpg / jpeg / bmp / gif，转成 `cover.png` 存入视频集文件夹 |
| 提取首帧为封面 | 取第一集的首帧，**按原分辨率**保存为 `cover.png` |

> 封面不自动生成，需要手动选择其中一种方式。竖版海报与横版截图都会等比缩放居中显示，不会拉伸变形。

### 搜索

在顶栏搜索框输入关键字：

- **视频集**：按名称实时过滤，以卡片形式展示
- **视频**：按文件名模糊匹配（如输入「第05集」），点击结果**直接跳转到该集播放**

### 观看进度

- 视频集卡片左下角显示状态角标：`看到 N/M 集` / `✓ 已看完` / `未看 0/N 集`，封面底部有整体进度条
- 播放列表每集显示状态图标与单集进度条：正在播放 / 已看完 / 看到 mm:ss / 未看
- 打开视频集时自动用 OpenCV 补全缺失时长，使进度百分比准确
- **打开视频集会自动跳转到上次观看的那一集并续播**；进度在「退出程序 / 返回首页 / 切换到其他集」时保存（忽略小于 3 秒的零碎进度）

### 进度预览与缩略图

鼠标**悬停进度条**会弹出预览窗：上方是目标位置的画面，下方是目标时间。预览窗**横向跟随鼠标、纵向固定在进度条上方**，鼠标压到窗口边缘时自动贴边，不会被裁掉。

画面有两条来源，按优先级自动选择：

| 来源 | 说明 |
|---|---|
| **缩略图雪碧图**（首选） | 把整段视频抽帧拼成一张大图并落盘；悬停时直接裁一格，**微秒级、完全不解码** |
| 实时抽帧（兜底） | 该位置尚未生成缩略图时，交给后台线程抽帧，**界面零阻塞**；结果按「每秒一格」缓存复用 |

> **为什么是「关键帧」而不是「固定间隔」**：H.264 的关键帧（I 帧）间隔通常接近 10 秒（实测样本为 9.92 秒）。以前用 OpenCV 按时间定位时，它必须 seek 到前面的关键帧再**逐帧解码追到目标帧**，单格要解约 162 帧、耗时约 480 ms。现在改成先扫出关键帧索引，再把每格锚定到离名义时间最近的关键帧——**每格只需要解 1 帧**。同时格子记录的是真实时间戳，预览窗显示的时间与画面严格一致。单部 24 分钟影片的生成耗时从约 48 秒降到约 10 秒（冷缓存）。

#### 生成缩略图

三种方式，任选其一：

- **首次打开某个视频集**时自动询问是否生成（每个视频集只问一次）
- 菜单 **文件 → 预加载全部预览图**（整个媒体库）
- 首页标题栏右侧的**下载图标按钮**（等同上一项）

生成期间底部状态栏显示进度与**取消**按钮，可随时中断；已生成的格子会保留，下次自动从断点继续。

- **只在首次生成，之后永久复用**：缓存以「文件路径 + 大小 + 修改时间」为键，视频文件一变自动失效重建
- 生成时会把每个视频切成多段**并行处理**（最多 4 个子进程），会短时占用一部分 CPU
- 若运行环境缺少 PyAV，会自动退回 OpenCV 的等间隔方案：功能不变，但生成会慢很多

#### 预览图间隔

菜单 **设置 → 预览图间隔**，可选 **每 5 / 10 / 20 / 30 秒**，默认**每 10 秒**。

间隔越小画面越细腻，但格子数、生成时间与缓存体积同比放大。以一部 45 分钟的视频为例：

| 间隔 | 大致格数 | 大致生成耗时 |
|---|---|---|
| 每 5 秒 | 约 540 格 | 约 40 秒 |
| 每 10 秒 | 约 270 格 | 约 20 秒 |
| 每 30 秒 | 约 90 格 | 约 8 秒 |

> 耗时取决于机器性能与视频编码，以上仅供参考。修改间隔后**已生成的缩略图需要重新生成**才会按新间隔显示（应用会提示）。超长视频会自动放宽间隔，把格数压在 1200 以内，避免雪碧图过大。
>
> 「预览图间隔」和「预览图精细度」**任一改变都会让旧缩略图失效**（格子的时间表与像素尺寸都变了）。失效的缓存会被应用自动删除，下次播放时按新参数重新生成——不会留下既用不了又占地方的半成品。
>
> 受关键帧间隔限制，实际格间距不会小于视频的 GOP（通常 2~10 秒）；把间隔设得比 GOP 还小并不会更细腻。

#### 预览图精细度

菜单 **设置 → 预览图精细度**：

| 档位 | 画面尺寸 | 说明 |
|---|---|---|
| 标准 | 240×135 | 与旧版预览窗同尺寸 |
| **高清**（默认） | 320×180 | 推荐 |
| 超清 | 480×270 | 画面最大 |

预览窗尺寸与抽帧分辨率**始终一致**（都由这里决定），画面像素直接铺满窗口，不会出现「小图放大显示」的模糊。早先的版本抽的是 160×90，却塞进 240×135 的窗口放大 1.5 倍显示，所以糊。

> 调大档位几乎不增加生成耗时——主要成本在于解码，与输出尺寸基本无关；只增加缓存体积。一部 24 分钟影片在「每 10 秒」下的雪碧图约为 1.2 MB（标准）／1.8 MB（高清）／3.3 MB（超清）。改动后同样需要**重新生成**，且不同档位之间不会复用缓存。

### 主题与音频

- **主题**：启动时自动检测系统颜色模式并应用 Material 3 深 / 浅色方案；菜单「主题 → 深色模式 / 浅色模式」可手动切换
- **音频**：菜单「音频」列出系统所有音频输出设备，可随时切换（如扬声器 / 耳机 / 蓝牙）

## 数据存储

- 数据库：`data/videos.db`（SQLite，含 `groups` / `collections` / `videos` 三张表）
- 封面：视频集文件夹内的 `cover.png`
- 缩略图缓存：**存在视频集文件夹里**，每个视频一对 `<视频名>.storyboard.jpg` + `.json`，与视频一起拷贝到别处可直接复用，不用重新生成；删掉也不影响播放，下次按需重建
- 视频文件**不做拷贝**，数据库保存原始文件路径

## 已知限制

- 目录扫描为**单层**：视频集就是所选文件夹本身，不递归子目录
- 每个视频集的封面固定为唯一的 `cover.png`
- 播放由 libmpv 负责，格式兼容性远好于 QtMultimedia，但需要随包携带约 115 MB 的 `libmpv-2.dll`
- 跳转（快进/快退/拖进度条）仍需回溯到前一个关键帧再解码追帧，实际停顿取决于视频的 GOP（本库样本约 9.9 秒），这是编解码层面的限制
- 缩略图会按视频的关键帧取样，实际格间距受 GOP 限制（见上文）
- 生成缩略图时会短时占用最多 4 个 CPU 核心；把「预览图间隔」调大可以减少生成量
- 预览图间隔越小，格子数与缓存体积越大（超长视频会自动放宽间隔，格数上限 1200）
- 安装包体积较大（PyQt6 + OpenCV + PyAV 的 FFmpeg + libmpv，约 115 MB）；其中 libmpv 一家就占 115 MB 未压缩、约 30 MB 压缩后
